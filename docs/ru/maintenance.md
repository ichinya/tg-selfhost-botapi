# Обслуживание

## Сборка образа

Workflow проверяет официальный исходник tdlib и digest Alpine 3.22 каждую ночь
около **04:37 Asia/Yekaterinburg** (23:37 UTC), при изменении основной ветки и
вручную. GitHub может задерживать запуск по расписанию.

Ключ сборки учитывает ревизии/digest, рецепт, entrypoint, патч и проверки образа.
Если соответствующий образ уже опубликован, компиляция пропускается.
Если проверка registry не подтвердила наличие образа, выполняется новая сборка.

Для нового образа workflow:

1. Проверяет применимость патча User-Agent к выбранной официальной ревизии.
2. Компилирует весь сервер.
3. Выполняет `--version`, проверяет строку заголовка в бинарнике и синтаксис entrypoint.
4. Публикует `ghcr.io/ichinya/tg-selfhost-botapi:build-<key>` и продвигает `latest`.

Ошибка проверки оставляет прежний опубликованный `latest`. Из PR публикации нет.
Наличие строки в бинарнике не заменяет проверку доставки реального webhook.

Для расписания и публикации workflow должен быть в основной ветке. Запись в GHCR
использует `GITHUB_TOKEN` с `packages: write`. После первого выпуска настройте
публичность пакета либо авторизацию клиентов.

## Обновление установки

Публикация в registry не перезапускает VPS. Выберите проверенный тег/digest через
`BOTAPI_IMAGE` в `.env`, затем:

```sh
docker compose stop botapi
# Здесь сделайте согласованную копию ./data и приватной конфигурации.
docker compose pull botapi
docker compose up -d --no-deps botapi
docker compose logs --tail=100 botapi
```

Для локальной сборки последовательно используйте build override:

```sh
docker compose -f docker-compose.yml -f docker-compose.build.yml stop botapi
# До замены бинарника сохраните ./data и приватную конфигурацию.
docker compose -f docker-compose.yml -f docker-compose.build.yml build botapi
docker compose -f docker-compose.yml -f docker-compose.build.yml up -d --no-deps botapi
```

Сохраните `./data`, владельца `101:101`, endpoint и local mode.
Не запускайте два процесса Bot API с одним каталогом данных. Для возврата старого
образа может понадобиться совместимая резервная копия состояния: одного отката
бинарника недостаточно для гарантии.

После обновления проверьте журналы и отправьте тестовое сообщение боту,
который уже работает на этом сервере. Проверьте фактический webhook, состояние
доставки и User-Agent в журнале принимающего сервиса.

## Диагностика

```sh
docker compose ps
docker compose logs --tail=100 botapi gateway
docker compose exec botapi telegram-bot-api --version
```

Перед публикацией журналов уберите токены, API hash, webhook-секреты и
чувствительные URL. Разделяйте доступность инфраструктуры, авторизацию бота и
доставку обновлений.

### Ошибки registry, сборки и запуска

| Симптом | Класс | Проверка / действие и ожидаемый результат |
| --- | --- | --- |
| Итоговый `unauthorized` или `denied` | Авторизация / права | Проверьте registry, reference, права пакета и пользователя/credential store как при login; повторите нужный pull с разрешённым доступом. |
| Нет repository, tag или digest | Reference | Проверьте написание, публикацию и видимость; выберите существующий reference. |
| `no matching manifest` | Платформа | Сравните архитектуру хоста с опубликованными платформами; выберите поддерживаемый образ. |
| 429 pull rate limit | Квота загрузок | Проверьте действующие лимиты Hub и дождитесь восстановления квоты; авторизация может изменить применимый лимит. |
| 429 abuse limit | Частота запросов | Снизьте частоту и примените backoff; вход не гарантирует исправление. Не исчерпывайте лимиты намеренно. |
| DNS, timeout или TLS | Сеть | Проверьте DNS, proxy, маршрутизацию и доверенные CA daemon; host curl и daemon могут использовать разные пути. Восстановите связь и доверие. Не отключайте TLS и не используйте insecure registries как обход. |
| Нет соединения с daemon | Docker daemon | Проверьте состояние daemon и права пользователя; восстановите доступ. |
| Registry 5xx | Сервис registry | Проверьте состояние registry и повторите позднее с backoff. |
| Ошибка APK/GitHub или OOM при сборке | Зависимости / ресурсы | Изучите очищенный вывод сборки и ресурсы; восстановите доступ или ресурсы до повтора. Login в Hub здесь не решение. |

Ответ 401 challenge от registry `/v2/` может быть штатным и сам по себе не означает ошибку авторизации. Успешный host curl не доказывает успешный pull через daemon.

```sh
curl --connect-timeout 5 --max-time 10 -sS -D - -o /dev/null https://registry-1.docker.io/v2/
```

HTTP 401 с `WWW-Authenticate` — ожидаемый challenge и признак доступности endpoint из shell, не доступа к образу. Нужный pull проверьте отдельно. DNS, TLS, timeout и 5xx разбирайте по соответствующим веткам выше; context, DNS, proxy и CA daemon могут отличаться от shell. PAT для запроса не нужен.

Для runtime используйте `docker compose ps`, `docker compose logs --tail=100 botapi gateway` и `docker inspect --format 'name={''{.Name}} status={''{.State.Status}} exit={''{.State.ExitCode}} restarts={''{.RestartCount}} image={''{.Image}}' tg_botapi tg_gateway`. Проверьте занятый порт, коды выхода и цикл перезапусков; немедленный выход botapi с `TELEGRAM_API_ID is required` указывает на отсутствующий или незаполненный `.env`. Сравните ID образов контейнеров с записанными. HTML 404, 502/504 или неверный upstream не проходят readiness: проверьте маршрут gateway и журналы. После замены botapi повторите проверку gateway; при необходимости перезапустите gateway и проверьте снова, не предполагая автоматическое обновление nginx.

При ошибке запуска локально проверьте владельца каталога данных и credentials приложения. Журналы просматривайте локально, перед публикацией удаляйте API hash, токены, webhook-секреты и URL. После пересоздания nginx может сохранить старый адрес upstream: сначала проверьте состояние и identity, затем при необходимости перезапустите выбранный gateway и повторите probe.

После обновления повторите [проверки binary, identity и readiness](getting-started.md#запуск), сохраняя build override для локального режима. Доставка назначенному боту проверяется отдельно после этого.

В отчёт включите revision, версии Docker/Compose, архитектуру, режим, reference/digest, ID образа контейнера, этап, код выхода и очищенную ошибку. Исключите `.env`, Docker config, полный inspect контейнера и неочищенные журналы.
## Документация и участие

Инструкции находятся в `docs/en` и `docs/ru`. При изменении поведения обновляйте
обе версии. Короткий корневой README ссылается на эти инструкции.

Pages использует Jekyll и уже настроенный источник `main /`. В `_config.yml`
заданы базовый путь и навигация, `_layouts/default.html` — общий шаблон.
`jekyll-relative-links` преобразует Markdown-ссылки для сайта, сохраняя их
работоспособность при чтении на GitHub.

Прежний URL `tg_selfhost_botapi_migrator.html` сохранён. Изменения документации
собираются в PR без публикации; после слияния в `main` их публикует действующая
интеграция Pages.
